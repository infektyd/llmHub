### Still Needs Work (Phase 3 🔨)

#### 1. 🔴 Build Errors — GroupChatOrchestrator Actor Isolation (CRITICAL)
Two MainActor isolation errors blocking compilation:

**Error 1 — Line 93:**
```
Main actor-isolated initializer 'init(agentId:contextId:orderIndex:status:content:)' cannot be called from outside of the actor
```
- `streamSingleAgent` is `nonisolated` but creates `AgentResponseState`
- Fix: The state snapshot should be fine since `AgentResponseState` is a struct with `var` fields... but the init might need to be explicitly `nonisolated`

**Error 2 — Line 101:**
```
Main actor-isolated initializer 'init(baseURL:)' cannot be called from outside of the actor
```
- `AgentRoutingService()` is called from `nonisolated streamSingleAgent`
- `AgentRoutingService` is `@unchecked Sendable` but its init creates `OpenClawManager(baseURL:)` which might be `@MainActor`
- Fix: Create `AgentRoutingService` instance before entering the detached task (in the `startStreaming` function where `@MainActor` is already available), then capture it in the detached task closure

**Approach**: Make `AgentRoutingService` a `@MainActor` actor (or at minimum make its init nonisolated), OR move its creation to `startStreaming` where it's already in a `@MainActor` block, and capture it in the detached task.

#### 2. 🟡 Multi-Agent Response Headers — Enhanced Richness
The current `multiAgentResponseRow` in `TranscriptView.swift` shows basic text. Upgrade to match `TranscriptRow` richness:
- Agent avatar with color ring
- Role description subtitle
- Status badge (ProgressView for thinking/streaming, checkmark for complete)
- Timestamp of when agent finished
- Tool run bundling preview (if agent used tools)

#### 3. 🟡 Clickable Agent Headers
When user taps an agent's name/avatar in a `TranscriptRow`:
- Show a popover/sheet with agent details (name, emoji, role description)
- Show "Reply to @agent" action — sends a DM to that agent in group chat context
- Show "Copy agent ID" for debugging

#### 4. 🟡 Group Chat Reply Threading
Currently `parentMessageID` supports replies. In group chat:
- When user taps "Reply" on an agent's message → should create a thread reply
- Show reply chain indicator connecting agent → user reply → agent response
- Thread connector lines should be colored by the agent that was replied to

#### 5. 🟢 Cross-Agent Message References
When one agent mentions another (e.g., `@forge mentioned @recon`), render as a clickable link:
- Tap → navigates to that agent's message in the transcript
- Visual: agent emoji + name as a pill/tag

#### 6. 🟢 Tool Run Bundle in Multi-Agent Streaming
When a multi-agent streaming row shows a completed response:
- If the agent used tools, show a collapsed "X tools ran" bundle below the message
- Expand on tap to see individual tool results
- Currently `multiAgentResponseRow` only shows raw text — need to parse and render artifacts

#### 7. 🟢 Composer Multi-Agent Support
The `Composer` view needs to support group chat:
- `@mention` autocomplete for discovered agents (already partially done with `AgentAutocompleteView`)
- Show which agents will respond before sending (agent chip list)
- Composer should show a "Group chat: @syntra, @forge, @recon" indicator

#### 8. 🟡 Session History — Multi-Agent Message Display
When loading a saved session with multi-agent messages:
- `TranscriptRowViewModel` already has `senderAgentID` — needs rendering
- Each agent's message should show their avatar/name in history
- Group chat sessions should show the multi-agent indicator in the chat header

#### 9. 🟢 Notifications / Completion Audio
When all agents finish:
- Flash the dock icon or show a notification
- Play a subtle completion sound (configurable)
- Badge the conversation as "updated"
